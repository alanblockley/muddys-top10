# Review Workflow

## Principle

Generated campaign content is a draft until a human approves it.

The system should optimize review speed while keeping editorial ownership with
the reviewer.

## Status Lifecycle

```text
draft -> revising -> reviewed -> approved -> published
```

Allowed status meanings:

- `draft`: generated by the system and not yet reviewed
- `revising`: a new revision is being generated or reviewed
- `reviewed`: human has inspected it and requested no immediate regeneration
- `approved`: ready to use externally
- `published`: manually marked as published or posted by a future integration

## Revision Principle

Campaign content should be revised immutably.

```text
Campaign
  -> active_revision_id
  -> approved_revision_id

CampaignRevision v1
CampaignRevision v2
CampaignRevision v3
```

Regeneration or chat/refinement creates a new revision. It does not mutate an
approved asset in place.

## Review Screen Requirements

A future admin UI should show:

- source chart week and snapshot key
- generated infographic PNG first, with download link
- social copy by channel
- DJ on-air reads per track
- chart summary and notables as source/reference data
- generation timestamp
- model and prompt/context versions
- template id/version
- brand config snapshot
- validation checklist results

## Review Actions

Required actions:

- regenerate full campaign
- regenerate only radio reads
- regenerate only infographic content
- regenerate only social posts
- refine a campaign revision with a specific instruction
- rate an asset up/down with optional free-text feedback
- edit draft copy manually
- mark reviewed
- approve
- mark published

## Audit Trail

Each campaign draft should preserve:

- original generated content
- current edited content
- active revision id
- approved revision id
- reviewer identity when available
- reviewed timestamp
- approved timestamp
- published timestamp
- regeneration count
- source `week_id`
- source `snapshot_key`
- context file hashes
- prompt ids and versions
- template id and version
- brand config snapshot

Each campaign revision should preserve:

- parent revision id
- source user instruction, if any
- generated HTML/CSS
- rendered PNG S3 key
- prompt versions
- template version
- model id
- validation results

## Feedback Loop

Feedback is stored separately from campaign content.

Use feedback for:

- AgentCore Memory summaries
- recurring preference detection
- prompt optimisation datasets

Do not use feedback to:

- automatically replace production prompts
- mutate approved campaign revisions
- override chart facts

Prompt optimisation should remain a manual admin-triggered workflow with A/B
comparison and explicit promotion.

## Failure Handling

If an agent reports missing inputs, store the failed draft with:

- failure status or validation flag
- missing input list
- partial outputs if safe/useful
- source chart brief
- generation metadata

The reviewer should be able to fix context/config and regenerate.
